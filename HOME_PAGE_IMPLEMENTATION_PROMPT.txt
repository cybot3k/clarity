2. NON-NEGOTIABLE RULES (violating any of these is a failed implementation)
--------------------------------------------------------------------------------
- No hardcoded visual values. No hex colors, no raw `fontSize`, no raw spacing
  or radius numbers outside `constants/`. A genuine optical one-off may stay
  inline ONLY with a comment explaining why.
- Colors resolve through `useTheme()`. NEVER `useColorScheme()` plus a local
  light/dark map.
- All words render via `<ThemedText variant=… tone=… />`. Weight comes from
  the `weight` prop (which maps to a `fontFamily`), NEVER the `fontWeight`
  style property.
- Frosted/glass surfaces use `<GlassSurface>` (or the raw `GlassView`/
  `expo-glass-effect` exactly as the existing chrome files already do).
  Nested `GlassView` does not render on iOS 26: a card whose child needs glass
  renders its `GlassSurface` as an absolute-fill SIBLING, never a nested child.
- Icons are Hugeicons Free via `<HugeiconsIcon icon={...} size={...} color=…/>`
  from `@hugeicons/react-native`, with the icon symbol imported from
  `@hugeicons/core-free-icons`. NEVER guess an icon name. Before importing an
  icon you are not 100% sure exists, run:
      glob "node_modules/@hugeicons/core-free-icons/dist/*<Keyword>*"
  and use the exact export name it returns. Never use emoji or any other icon
  library.
- Do not add Skia, `expo-linear-gradient`, shadow styles, or elevation. This
  app has no shadow token set on purpose — depth comes from glass and mesh
  gradients only.
- NO dot-matrix, LED, or segment-style digits anywhere. All numerals render
  as plain SF Pro Rounded through the existing `ScoreValue` component (or
  plain `ThemedText` with `fontVariant: ['tabular-nums']` where `ScoreValue`
  doesn't fit). `components/ui/led-number.tsx` and `components/ui/metric-
  capsule.tsx` are NOT used by anything you write. Do not delete them in this
  pass — `app/(tabs)/analytics.tsx` still imports `MetricCapsule` and that
  screen is out of scope here.
- Do not invent copy. Every string you render must already exist in the repo
  (in the files listed below) or be an existing data value formatted the way
  the current code already formats it (e.g. "12 min", "82 /100"). If a slot in
  the design contract has no existing string backing it, OMIT the slot —
  do not write a new sentence to fill it.
- Do not change routes, navigation targets, scoring math, Convex, Clerk, or
  any business logic. This is a visual/layout diff only. Every `router.push`
  / `router.navigate` target stays exactly what it is today unless this brief
  explicitly says otherwise (it does not).
- Screens import components; components import tokens. `app/(tabs)/index.tsx`
  may use `spacing` directly for its own layout (margins/gaps between the
  blocks it composes), but it may not name a color, a font size, or a radius.
- Preserve every bit of existing functional behavior in files you edit
  (loading states, error alerts, accessibility labels/hints, haptics). Only
  change what this brief tells you to change.
- Skip formatters, linters, and the full test suite while you work. Run a
  TypeScript check only at the very end (see section 8), and fix whatever it
  reports in the files you touched.
